# OshiDeck

YouTube Live Chatのコメントやメンバー絵文字の組み合わせを保存し、ワンクリックで呼び出せるChrome拡張機能です。

バージョンは `manifest.json` にあります ── ここに書き写すと、片方だけ古くなるので。
直した挙動は patch、見える変化は minor。配布されるファイルを変えて version を
据え置いたコミットは `tools/hooks/pre-commit` が止めます ── 一度、十四コミット
ぶん据え置いたままにしたので。

## Features

- コメントやメン限スタンプの組み合わせを「札（カード）」として保存
- 札はカード名を持たず、中身そのものがラベル
- **手札モード** — 札が扇状に並ぶ。幅に合わせて1行の枚数が自動で増減（400pxで7枚、760pxで14枚）
- **リストモード** — 1行1枚。幅が広いほど欄が増える
- カードプール（保存した札はすべてここ）とデッキ（そこから選んで並べたもの）の2階層
- 同じ札を複数のデッキに入れられ、デッキごとに別の位置を持てる
- チャンネルごとの推し色が札の上端に出る
- 並び順は「チャット連動 / 最近よく使う順 / 使った回数順 / 自分で並べた順」── 既定はチャット連動
- **チャット連動** — いまチャットで流れている反応に合う札を前に出す
- **チャットから引く** — 部屋が沸いたとき、持っていない反応を1枚だけ手札の左に差し出す
- **プリセット** — そのチャンネルの常連が使っている札を、まとめて、または1枚ずつ
- 同じ札を何度も繰り返す札は `🪽🫧🎶×2` と数えて出す
- 標準の絵文字は、チャットが実際に描いているYouTubeの画像で出す
- 使った回数はチャンネルごとに数える
- クリックで入力欄へ、`⇧` ＋ クリックでその場から送信
- メン限スタンプは持ち主のチャンネルを判定し、送れない配信ではロック表示
- 削除は取り消しトースト付き（確認ダイアログでページを止めません）
- スーパーチャットが同じ隅を使うときは、パネルのほうが身を引く
- うまくいかないときのための診断ログ（設定ページから書き出せます）
- JSONでの書き出しと読み込み（追加 / 全部置き換え）
- `chrome.storage.local` によるローカル保存

## Install

1. このリポジトリをCloneまたはDownloadします。
2. Chromeで `chrome://extensions/` を開きます。
3. 「デベロッパー モード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」を選択します。
5. OshiDeckのフォルダを選択します。
6. YouTube Live / Premiere のチャットを開きます。

## Usage

1. YouTubeの通常のチャット入力欄でコメントを作ります。
   - `🦢✨🦢✨🦢✨`
   - `👏👏👏👏👏`
   - `はい！はい！はい！はい！`
   - YouTubeの絵文字ピッカーからメン限スタンプを並べてもOKです。
2. OshiDeckの「保存」を押すと、そのまま札になります。名前を付ける必要はありません。
3. 配信ページで保存した札はそのチャンネルのデッキに入り、次に同じチャンネルを開くと自動で出てきます。
4. 札をクリックすれば入力欄へ復元、`⇧` ＋ クリックでそのまま送信。

札の上端の色がスコープです — グレーが共通デッキ、色つきがそのチャンネルの札。色はチャンネルごとに自動で割り当てられます。

## Auto Send

設定ページの「札をクリックしたら自動で送信する」をオンにすると、札を入れた直後に送信します。初期値はオフです。

オフのままでも `⇧` ＋ クリックでその場から送信できるので、普段は入力欄に入れるだけ・確信があるときだけ即送信、という使い分けができます。

## Notes

OshiDeckはYouTubeの公開APIではなく、Live ChatのDOMを利用しています。
そのためYouTube側のHTML構造が変更された場合、調整が必要になる可能性があります。

メンバー絵文字はYouTubeが入力欄で使用している以下のDOM形式を再現しています。

```html
<img
  class="emoji yt-formatted-string style-scope yt-live-chat-text-input-field-renderer"
  src="..."
  alt="..."
  data-emoji-id="..."
>
```

### Scope survives everything

保存された scope は、その札に何ができるかを決める唯一の答えです。ただし
**メン限スタンプのほうが強い** —— 古いビルドや手で書き換えたバックアップが
「メン限入りなのに共通」という札を持ち込んでも、内容から強制的に上書きします。

過去のどの形式から移行しても、当時の意味をそのまま引き継ぎます。

| 形式 | 何が「そのチャンネルの札」を表していたか |
| --- | --- |
| v0.1 / v0.2 | `presets.channels[X]` に入っていること |
| v0.3 | 札の `scope` フィールド（今と同じ意味） |
| v0.4 以降 | メン限スタンプを含むこと |

読み込み時に、そのデッキが送れない札への参照は落とします。古いビルドが作れた状態で、
画面にも出せず操作もできないためです。

バックアップは format 2 になりました。format 1 も読めますが、そちらには scope が
無いので当時の意味（メン限入り＝専用、それ以外＝共通）で補います。

## Which deck a card goes to

保存先は押すボタンで決まります。上の帯は入力欄の中身に合わせて姿を変えます。

```
入力欄が空のとき   ● さくらチャンネル ＋ ● 共通   14枚          [編成]
何か入力したとき   保存先  [＋ さくらチャンネル] [＋ 共通]      [編成]
```

札のスコープ帯（手札モードなら上端、リストモードなら左端）は**読むためのもの**です。
保存したあとで変える手立ては、いまのところUIにありません ── `setScope` は store にありますが、
どちらのページからも呼んでいません。変えたいときは外して保存し直してください。

メン限スタンプ入りの札は共通デッキに入れられません。配っているチャンネル以外では
そもそも送信できないためで、「共通」ボタンは無効になり、理由がツールチップに出ます。

## One writer

配信ページのパネルと編成ページは同じデータを変更しますが、**どちらも直接は書きません**。

`chrome.storage` には compare-and-set がありません。両方が read を終えてから
どちらかが write すると、負けた側の変更は跡形もなく消えます。実際に測ると、
使用回数の記録と並べ替えを同時に走らせただけで片方が失われます。

そこで変更は「名前の付いた操作」として service worker に送り、worker が
**1つずつ順番に**最新状態へ適用します（`background.js` のキュー、`src/store.js` の `OPS`）。

```
content.js ─┐
            ├─→ chrome.runtime.sendMessage({ type: "mutate", op, args })
options.js ─┘        ↓
              background.js  … 直列キュー
                     ↓
              read → 適用 → 1回の set()
```

守っていること。

- **1操作 = 1回の `set()`**。互いを参照する `cards` と `decks` が食い違う瞬間がありません。
  ドラッグでの「追加して位置を決める」も、読み込みも、1操作です
- **判断も worker の中で**。重複の有無、そのチャンネルで使える札かどうか、
  バックアップのマージ結果 —— どれも呼び出し側のスナップショットではなく、
  worker が読み直した状態に対して決めます
- **取り消しも操作**。押すまでの間に相手が動いていても、消えた札は戻さず、
  すでに戻っていれば二重に入れず、その後に付いた名前や色は巻き戻しません
- **`read()` は読むだけ**。古い形式からの移行もメモリ上で行い、
  最初の操作が worker 側で書き込みます
- 書き込みに失敗したら入力欄は消さず、成功したとも言いません

`settings` も同じ経路です。直接書いていたころは、設定のクリックと読み込みが重なると
あとから着いたほうがもう片方を消していました。

### Two kinds of card

札は「**共通**」か「**そのチャンネル専用**」のどちらかです。これは内容から推測するもの
ではなく、**保存するときに選ぶ札自身の性質**です。

```
保存先  [＋ さくらチャンネル] [＋ 共通]
```

- **共通** — どのチャンネルのプールにも出て、どのデッキにも入れられます
- **チャンネル専用** — そのチャンネルのプールにしか出ません

`888` のような普通のテキストでも「さくら専用」にできます。逆に、メン限スタンプを
含む札は**共通にできません**（他のチャンネルでは物理的に送れないため）。その場合は
「共通」ボタンが無効になり、理由が出ます。

あとから変える手立ては、いまのところUIにありません（[Which deck a card goes to](#which-deck-a-card-goes-to)）。
store の `setScope` は、変えたときに送れなくなったデッキから自動で外すところまで書けていますが、
どちらのページからも呼んでいません。

配信ページ以外ではチャンネルが分からないので、共通の札としてプールに入ります。

## Pools are per channel

プールはチャンネルごとにあります。中身は「**どのデッキでも使える札**」＋「**そのチャンネル専用の札**」。

```
さくらのプール:  888  わこつ  [さくらのスタンプ]
ゆめののプール:  888  わこつ  [ゆめののスタンプ]
                 └─ 共通札はどのプールにも出る
```

他のチャンネル専用の札は出てきません。見えても使えない札が並ばないので、
プールに入っているものは必ず今のデッキに入れられます。

そのおかげで「外す」の意味がどこでも同じになります。デッキから外した札は
自分のチャンネルのプールに戻るだけで、消えることも、行方不明になることもありません。

| 場所 | できること | 影響 |
| --- | --- | --- |
| 配信ページ | 打つ / 編集 / **⏏ このデッキから外す** | このデッキだけ |
| 編成・デッキ欄 | **⏏ 外す** | このデッキだけ。札はプールへ |
| 編成・プール欄 | **× 削除** | すべてのデッキから消える |
| 編成・左の一覧 | **× デッキごと削除** | 共通の札は残り、**そのチャンネル専用の札は一緒に消えます** |

取り返しのつかない削除は編成ページのプール欄だけに置いています。すべて「元に戻す」が付きます。

## Pool and decks

保存した札はすべて**カードプール**に入ります。**デッキ**はそこから選んで並べたもので、
配信ページに出るのはデッキだけです。プールに入れただけの札は自動では出てきません。

```
カードプール          888  わこつ  はいはい  🎉  おつかれ  GG
                       │      │        │
さくらチャンネルのデッキ   888  はいはい   🎉
ゆめのチャンネルのデッキ   GG   888
```

- 同じ札を複数のデッキに入れられます
- **並び順はデッキごと** — 同じ札がさくらでは先頭、ゆめのでは末尾、ということができます
- **使った回数もデッキごと** — 下記
- **デッキから外す**（⏏）とプールに残ります。**削除**（🗑）はプールから消え、すべてのデッキから外れます
- 配信ページで保存すると、プールに入ると同時にそのデッキにも入ります（2手間にしないため）
- すでにプールにある札と同じ内容を保存すると、複製せずにその札をデッキに入れます

配信ページのパネルからは帯の「プール N」を押すと開き、札をクリックするとデッキに
入ります。全部の編成は設定ページで行います。

### どれだけ使ったかは、チャンネルごとの話です

使った回数は札の性質ではなく、**その部屋での習慣**です。`👏` をあるチャンネルで50回押したことは
隣のチャンネルについて何も言っていないのに、1つの数を共有していたころは、**そこで一度も押した
ことのない札が手札の先頭に居座って**いました。

なのでカードは `by` の下にチャンネルごとの数を持ちます。チャンネル限定の札はもともと
チャンネルが1つなので、そちらは何も変わりません。「最近よく使う順」「使った回数順」も、
編成ページの「$1回」も、いま見ているチャンネルの数を読みます。

**移行。** 以前の数がどのチャンネルで稼がれたものかは復元できません。そこで**その札が入って
いるデッキすべてにそのまま引き継ぎます** ── デッキ1つに入っている札（大半がそうです）なら
それが正解ですし、複数に入っている札でも、アップグレードで並び順を捨てない唯一の答えです。
次に押した時点から別々に育ちます。どのデッキにも入っていない札でも、**チャンネル専用なら
その数は残ります** ── そのチャンネルでしか使えなかったのだから、使われた場所は分かります。
共通の札だけは置き場所がないので落とします。

### まだ持っていない札も、そこから入れられます

入口はひとつですが、中は**2つに分かれています**。帯のラベルで切り替えます。

```
[手持ち 12][プリセット 10]                      [閉じる]
```

- **手持ち** ── 保存してあって、このデッキには入れていない札
- **プリセット** ── このチャンネルの常連が使っている札の**一組まるごと**（デッキに入れたものを除く）

プールにいるあいだはどちらも**破線の縁**です ── 引いた札と同じ意味で、押すまではデッキの
ものではありません。どちらの札かはラベルが言うので、札そのものには印をつけません。

**色帯はプールでも scope を言います。** 以前は「見ているだけでまだ出ていない」という理由で
プール内は全部グレーに塗っていましたが、入れるかどうかを決めている最中こそ scope が要る
情報です ── チャンネル限定の札はここでしか使えません。プリセット側はなおさらで、その札は
一度も見たことがないので、ほかに手がかりがありません。

混ぜては置きません。保存した札とプリセットが提案している札は別のもので、ひとつの列に
並べると「プールに入っていないのにプールにある札」になってしまいます。

**同じ札が両方に出ることはあります。** 2つは排他ではなく、**2つの問い**です ──
「手持ち」はその札がどこから来たか、「プリセット」はこのチャンネルの常連も使っているか。
持っているからといってプリセットから抜くと、10組のうち7枚を自分で保存した時点で
プリセットは3組として読めてしまいます ── 自分が同意した場所にだけ穴の空いた一覧です。

帯の入口のボタンが数えるのは**札の数**で、ラベルの足し算ではありません。10枚のうち9枚を
すでに持っているプリセットは、入れられる札が**1枚**であって19枚ではありません。手持ちだけを
数えると、まだ何も保存していないチャンネル ── どのチャンネルも最初はそうです ── で入口
そのものが出なくなります。

プリセットはもともと**全部か無か**で、しかも**デッキが空のあいだだけ**でした。10枚まとめて
入れるか何も入れないかで、自分の札を1枚入れた時点で入口が永久に消えます。プリセットが
何であるかから、そうなる理由は何もありません ── プリセットは札の一覧で、プールは札の
出どころで、まだ持っていない札も「このデッキに入れられる札」です。

1枚だけ押したときも通るのは `loadPreset` です。全部入れるときと同じ道なので、同じ内容の
札をすでに持っていれば新しく作らずそれを使う、という判断もそのまま効きます。

すでに持っている札は、プリセット側でも**あなたのその札**として出ます ── 押すと、その ID も
色もこのチャンネルで稼いだ回数も持ったままデッキに入ります。同じ言葉の2枚目は作りません。
デッキに入っている札はどちらにも出ません ── プールは「まだ入れられるもの」です。
**同じ言葉かどうかで見ます。** デッキが持っているのは ID の一覧ですが、同じ言葉を別の ID で
2枚持っていることはある（このチャンネル用に1枚、どこでも使える札としてもう1枚）ので、
ID で訊くとデッキにある言葉のもう一方が提案され、押すと同じ言葉が2枚入っていました。

## Arranging from the stream

並び順が「自分で並べた順」のときは、配信ページのパネルでも札をドラッグして並べ替えられます。
編成ページを開かずに、配信を見ながら直せます。並び順はそのデッキだけのものなので、
他のチャンネルの見え方には影響しません。

手動モード以外では掴めるようにしていません。他の並び順は毎回計算されるので、
ドラッグしても次の描画で戻ってしまうためです（掴めるのに効かない、が一番わかりにくいので）。

クリックは従来どおりです。ブラウザのドラッグは数px動かして初めて始まるので、
配信中に押した札が「送信されずにドラッグになる」ことはありません。

## Deck builder

設定ページの上段が編成ページです（配信ページの「編成」ボタンから開きます）。
左からデッキ一覧・選んだデッキ・カードプールの3列。

```
デッキ
┌──────────┬────────────────────┬──────────────┐
│● さくら 12│ さくら              │ カードプール 9枚│
│● ゆめの  8│ 推し色 ●●●●●●       │ 🔍 絞り込む    │
│● ほしの 15│ ┌────┐┌────┐      │ ┌──┐┌──┐    │
│          │ │ 888││はい │      │ │おつ││GG │    │
│          │ └────┘└────┘      │ └──┘└──┘    │
│          │   ↑ ここに落として追加 │   ↑ ここから  │
└──────────┴────────────────────┴──────────────┘
```

プールを横に置くのは、そこからデッキへドラッグするのが編成の主な動作だからです。
縦に積むと、掴んでから落とすまでにスクロールが要ります。

推し色はチャンネル名の**下**に置いています。横に並べると見出しが幅を食い、
中央の列が細くなって札が1行に1枚しか入らなくなります。

設定の節も同じページ幅にそろえ、端を合わせています。中の行は1列のまま。
2列に畳むと、説明がいちばん長く選択肢も多い「並び順」がいちばん窮屈になりました。

- **プールからデッキへドラッグ** — 札の間に落とせば、その位置に入ります。追加と並べ替えが1動作
- **デッキからプールへドラッグ** — そのデッキから外れます
- **デッキ内でドラッグ** — 並べ替え
- 絞り込みはプールにかかります（探すのはこれから入れる札なので）
- すべての操作はステータス行の「元に戻す」で戻せます

### What the pool shows

プールはそのチャンネルに**まだ入れられる札**です。デッキに入れた札はプールから消え、
外せば戻ってきます。プール ＋ デッキで、そのチャンネルで使える札の全部になります。

出てくるのは「どのデッキでも使える札」と「そのチャンネル専用の札」だけ。
他のチャンネル専用の札は、見えても押せないので出てきません。

## Presets

そのチャンネルの常連が使っている札を差し出します。**まとめて一組**か、**プールから1枚ずつ**かの
どちらでも入れられます ── デッキが空のときはまとめて入れるボタンが出ますし、そうでなくても
プールの「プリセット」側にいつでも並んでいます（[Pool and decks](#pool-and-decks)）。

同梱しているのは**290組**、2889枚。過去のチャットから掘ったものです（下記）。

**プリセットはバックアップではありません。** バックアップは自分のところへ帰ってくるもので、ID も
使用回数もどのデッキが何を持っていたかも丸ごと戻します。プリセットは**他人のところへ行く**ので、
持っていくのは中身だけです:

- **IDは持っていきません** ── 読み込むたびに作り直します。保存はそれぞれの端末の中だけなので、
  同じIDが他人に届くわけではありません。困るのは**自分の中**で ── 同じプリセットを2回読んだり、
  あとでバックアップを合流させたりしたときに、別物であるべき2枚が同じ札として扱われます
- **使用回数も履歴も持っていきません** ── あなたがよく使ったことは、配った先には関係がありません
- **scope は `global` か `channel` のどちらか** ── `channel` は「読み込んだ先のチャンネル」という
  意味です。持ち主を名乗らないプリセットには、それがどのチャンネルか分かりようがないので、
  決めつけません

### 二種類あります

| | 名乗るチャンネル | メン限スタンプ | どこで出るか |
| --- | --- | --- | --- |
| **持ち運べるほう** | なし | 入りません | どのチャンネルでも |
| **そのチャンネルのほう** | `channel: "UC…"` | **そのチャンネルのものは入ります** | そのチャンネルだけ |

メン限スタンプを外していたのは、**プリセットが持ち主を名乗れなかったころの理屈**でした。どこにでも
配られる可能性があるなら、一箇所でしか使えないものは持たせられません。名乗れるなら話は別で ──
渡す相手は同じ配信者を見ている人たちなので、**その人もメンバーかもしれない**。外したままでは、
デッキの中でいちばん手間のかかった部分をまるごと捨てることになります。

書き出すと**自動でそうなります**。デッキにそのチャンネルのメン限スタンプが1枚でもあれば `channel`
が付き、無ければ付きません（名乗れば他所では出なくなるので、理由もなく狭めません）。

メンバーでない人が読み込んだら、その札は**鍵がかかって手札の最後に並びます**
（[Member emoji](#member-emoji)）── 消えはしないので、メンバーになればそのまま使えます。

よそのチャンネルのメン限スタンプは、名乗ったあとでも入りません。読み込み側も同じ判断をするので、
手で書き換えたファイルを別のチャンネルに読ませても、送れない札は入りません。

**書き出しと読み込みは、デッキの上にあります。** 編成ページの、デッキの名前の右にある2つの
小さなボタンです ── バックアップの節ではありません。あちらは**全体**（プール・全デッキ・設定）を
まとめて扱うもので、こちらは**このデッキ1つ**。同じ並びに4つ置くと、どれがどこまで効くのかは
ラベルを全部読まないと分からなくなります。

読み込みは、渡された側から見た同じ動作です。ファイルは拡張機能自身の検証を通り、
**よそのチャンネル専用のファイルはその場で断ります** ── 黙って読み込むと、いちばん手間の
かかったところ（メン限スタンプの札）だけが消えて、残りが入ってしまうからです。

### 何を言っているかを数える

プリセットの中身は、その配信の過去のチャットから拾えます。

```
tools/mine.sh UCeqIMtLuGc3YgwkhEaG8oDg
```

新しいほうから15配信ぶんのチャットを取ってきて、候補を並べます。**出てくるのは候補であって
プリセットではありません** ── どれを入れるかは好みの問題で、回数に好みはありません。

**15配信です。最初は6でした** ── 上位がどれだけ動くかを測って出した数で、測るものを間違えて
いました。いちばん大きな声は早く落ち着いてそのままですが、**あとから来るのは語彙のほう**です。
このチャンネルの新しい6配信は4つが歌枠で、彼女が喋る配信にしか出てこない反応のことば
（かわいい・すごい・いいね・わかる）は、候補に1つも入っていませんでした。15ならあります。

**種類を選り分けずに、新しい順で取ります。** 手で混ぜるには「その人の配信の内訳」を知っている
必要があり、それは1チャンネルを超えた時点で成り立ちません。数を増やすほうが、同じことを
勝手にやってくれます。

**人数で並べます。回数ではありません。** 数人が100連打したものが回数では一番上に来ますが、
それは部屋がやっていることではありません。ある歌枠では、両者の上位が完全に食い違いました。

**配信数では並べません。** 3配信以上を候補にする足切りには使いますが、そこから先は人数です。
配信数を先に見ていたころは、たまたま全15配信に出たものが、20人しか言っていなくても上に来て
いました ── このチャンネルの看板である `🦢✨` が、354人・11配信で28位に沈んでいたのです。
歌枠でしか出ないのは当たり前（彼女が歌っているあいだに送るものだから）で、喋る配信に無いことは
欠点ではありません。

メン限スタンプも拾えます（`:_tadaima:`・`:_curry:`）。よそのチャンネルのものと、誰でも送れる
無料の絵文字は外します ── 後者は[Member emoji](#member-emoji)のとおり、接頭辞だけを見ていると
取り違えるものです。

### ここだけの言葉か、どこでも言う言葉か

`scope` は数えただけでは決まりません。**「メン限ではない」は「共通」ではない**からです ──
`🦢✨` は稀羽すうの看板（名前が「羽」）ですが、文字そのものはただの絵文字で、誰でもどこへでも
送れてしまいます。よそへ送るのが単に間違いだ、というだけのことで、**それを知っているのは
よその部屋だけ**です（札にどう描かれるかは[Standard emoji](#standard-emoji)）。

```
tools/mine-org.sh ReAcT              # 事務所をまるごと（数時間、途中から再開できます）
tools/mine-org.sh --subscriptions    # 登録しているチャンネルを、並べた順に
node tools/scope.mjs UC… --take 10 --name 稀羽すう
```

**どのチャンネルからやるか**は `tools/subscriptions.json` の順です。**このファイルはリポジトリには
入っていません** ── 誰を登録しているかとその並び順は、その人のものであってプロジェクトの
ものではないからです。youtube.com/feed/channels を保存したものを `tools/subscriptions.mjs` に
読ませると、Holodex と突き合わせて書き出します ──
**並べた順がそのまま残ります**。登録者数より、本人が並べた順のほうが「次はどれ」の答えとして
まともです。

Holodex が知らないチャンネルは外します。名前からVTuberかどうかを当てようと
しても当たりませんでした ── 「VTuber」と名前に入っているのは1件だけで、配信の有無で絞っても
政治家や一般の配信者が残ります。Holodex は人が手で維持しているので、そちらを信じます。

`scope.mjs` は `tools/candidates/` にある全チャンネルぶんを読んで、一枚ごとに「よそでも**上位に**
あるか」を見ます。ある → `global` でどのプールにも出る。ここだけ → `channel` で留まる。メン限
スタンプはそもそも選べません（`forcedScope` が配っているチャンネルに固定します）。

**「よそにもある」では足りません。** 候補は数百件あり、その中に居るというのは「誰かが一度
言った」でしかないからです。`ただいま` は稀羽すうの挨拶ですが（配信の名前が「ここで待ってんのよ」
なので、視聴者は“ただいま”と帰ってくる）、よその3チャンネルにもありました ── 78位・78位・46位、
1〜3人ずつ。彼女の63人・622回に対してです。それを「よそでも言う」と数えると共通になってしまいます。

**上位20件まで**で二つは分かれます。その深さなら 👏 は35チャンネル中32、`ただいま` はゼロ。
10件まで狭めると、`うおおおおお`（4）や `はい！はい！はい！はい！`（9）まで剥がれてしまい、
そちらは本当に誰のものでもあります。

**何チャンネルで「よそでも言う」かは割合で見ます（2%）。** 数で決めると、掘るチャンネルが
増えたとたんに意味が変わるからです ── 比較対象が36のころ `ただいま` はゼロで「1つでもあれば
共通」は妥当でしたが、272になると2つに現れ、同じ規則が彼女の挨拶をまた共通と呼びました。

分布は二つの山に割れています。273チャンネル×10枚＝2619枚のうち、**1390枚はよその上位20に
一度も出てこず**、**568枚は半数以上に出てきます**。谷は2%（272の6チャンネル）のあたりです。
上には GG・わかる・おはよー・ばいばーい・88888・ナイス・待機。下には そう・wkwkwk・ないふぁい、
それに一度数えたものの綴り違いが並びます。

**共通になる札は、綴りを1つにそろえます。** scope は署名で決めるので `お`・`おおー`・`お！` は
ひとつの反応として数えますが、札に書かれるのは各チャンネルで一番多かった綴りです。273チャンネル
ぶんを合わせると、その一つの反応が**12枚の別々の共通札**になり、`w` が8枚、`👏` が4枚 ──
いくつか読み込んだ人のプールには、その全部が積み上がります。

なので共通になるものだけ、**全チャンネルを通していちばん多くの人が使った綴り**に寄せます。
相異109枚が56枚になり、減ったぶんはすべて同じことの言い換えでした（`こんばんは` は残ります）。
そのチャンネル専用の札はそのままです ── 合わせる相手がいませんし、その部屋の書き方こそが中身
だからです。

事務所まるごと掘るのは、札の候補のためでもあり、**互いの対照群になるため**でもあります。

**同梱するときは**、気に入ったデッキを書き出してから、

```
node tools/add-preset.mjs ~/Downloads/oshideck-preset-さくら.json
node tools/add-preset.mjs ~/Downloads/oshideck-preset-さくら.json --channel UC…
```

とすれば `presets/<チャンネルID>.json` として入り、`presets/index.json` に名前が載ります。
あとは commit するだけ。**同じチャンネルの組があれば
差し替えます** ── 名前ではありません。ひとつの空デッキに2組が出るのが困るのであって、
表示名が同じチャンネルが2つあっても一緒には出ないからです。
取り込む前に拡張機能自身の検証を通すので、**読み込み時に弾かれるものはリポジトリに入りません**。

**同梱するものは必ずチャンネルを名乗ります。** 配信の最初に何を言いたいかはその配信者のもので ──
合言葉も、掛け合いも、スタンプも ── どこでも通る挨拶の詰め合わせは、一度打てば済む話です。
メン限スタンプが入っていれば書き出しが勝手に名乗りますが、文字だけのデッキには名乗るものが
無いので、そのときは `--channel` で言います。

同梱の `presets/` には **290組** が入っています ── 掘ったチャンネルのチャットから、
常連の多い順に10枚ずつ。`tools/mine-org.sh` と `tools/scope.mjs --all` の出力そのままです
（Holodex の全チャンネルを順に掘っている最中なので、この数は増えます）。

読み込みは足し算です。同じ内容の札がプールにあれば、**コピーせず既にあるほうを使います** ──
同じ言葉の札が2枚あっても、どちらも同じ反応に答えてしまうだけなので。二度読んでも増えません。

ただし**同じ言葉であることと、同じ札であることは違います**。よその配信専用として保存した
`わこつ` はここでは打てないので、それを使い回すとデッキには何も入らないまま「読み込んだ」と
だけ言うことになります。同じ言葉の札は全部見て、**ここで打てるもの**を使います。

読み込みはチャンネルの名前も一緒に覚えます。名前はふつう札を保存したときに分かるものなので、
プリセットで始めたデッキは編成ページにIDのまま並んでいました。

同梱のファイルはサービスワーカーが読みます。拡張機能自身のファイルであって、YouTubeのページに
見せる理由が無いからです（`web_accessible_resources` に出すと見えてしまいます）。

### 1チャンネル1ファイル

同梱のプリセットは `presets/<チャンネルID>.json` に1組ずつ置いて、`presets/index.json` が
どれがどのチャンネルのものかを言います。ワーカーは起動のたびに index（いまのところ27KB）だけを
読み、そのあと**目の前のチャンネルの1組（4.4KB）だけ**を取りに行きます。

ひとつの大きなファイルだったころは、冷起動のたびに全部を `fetch` して `JSON.parse` していました。
その大きさは**誰かが掘ったチャンネルの数**で増えるのに、ひとりの視聴者が要るのは1組です ──
290組で1.25MB、Holodex の活動中チャンネルは2893あるので、同じやり方なら12.5MBを毎回読むことに
なります。分けたいまなら、そこまで掘っても冷起動で読むのは index の282KBだけです。

プリセットサーバー（[Roadmap](#roadmap)）はまだ要りません。要るとすれば、index そのものが
大きくなりすぎたときです。

## Export and import

設定ページのいちばん下から、プール・デッキ・チャンネル設定・表示設定をまとめてJSONに
書き出せます。ファイル名は `oshideck-YYYY-MM-DD.json`。

読み込みには2つのモードがあります。

| | 何をするか | 使用回数 |
| --- | --- | --- |
| **追加** | ファイルの札を今のプールに足し、デッキへの所属も足す | 既存の札は自分の回数を維持、新しく来た札は0から |
| **全部置き換え** | 今のプールとデッキを捨ててファイルの内容にする | ファイルの回数をそのまま復元 |

**追加**では、札は**idではなく内容で照合します**。同じコメントを別の環境で保存すると
uuidが違うので、idで見ると同じ札が二重になってしまうためです。結果として、
同じファイルを2回読み込んでも何も増えません。

**全部置き換え**は1クリックでは実行されません。ファイルを選ぶと枚数を表示して止まり、
「置き換える」を押して初めて適用されます。

ファイルは適用前に検証します。壊れたJSON、札の形式違い、存在しない札を指しているデッキは
理由を出して拒否し、一部だけ適用されることはありません。

実装は `src/backup.js`（純粋関数）と、設定ページ側の配線です。

## Reporting a problem

Options → 診断ログ → ファイルに保存 writes a text file of what the panel decided
and, when it decided nothing, what the page gave it to work with:

```
2026-09-06 18:52:04  channel ×9   video=Gv0g2GYipSM id=UCPb47… name=REVERBERATION via=card-by-handle
2026-09-06 18:52:23  unresolved   video=1nIxe0Gd7ZE ownerBlock=ytd-video-owner-renderer
                                  ownerLink=false handle=false cards=2 cardIds=["UCPb47…"]
                                  meta=false player=stale-or-absent
```

Every wrong-channel report so far arrived as a screenshot, and answering it
meant reopening the stream and reconstructing by hand what the page had looked
like at the time — which is exactly the line above. `via` names the source that
answered, so a channel that is merely *wrong* is as diagnosable as one that is
missing.

It holds the newest 300 entries; an observation repeated during a stream is
counted (`×9`), not copied, so an hour of watching cannot push the interesting
line off the end. Clearing it first and then reproducing gives the shortest
file. Channel ids, video ids and which selectors resolved are all it carries —
no card contents and no chat.

## Cards clip, never spill

札の中身は長さがまちまちです。スタンプ5個なら 110px 必要ですが、104pxの札に使える幅は
88pxしかありません。そのため中身の器は**折り返し・切り抜き・フェード**の3つを必ず持ちます。

- `flex-wrap: wrap` — フレックスの子は既定で折り返さないので、これがないとスタンプが
  一列のまま札の外へ押し出されます
- `overflow: hidden` を札そのものにも — 器から出たものを枠で止めます
- `max-width: 100%` と `min-width: 0` — フレックスの子は中身の幅で決まり、
  min-content より縮まないので、これがないと折り返さずに両端が切れます

### いっぱいとは何か

中身が入りきらなくなったら、札は**2段階で応えます**。まず一段小さくし、それでも足りなければ
もう一段小さくして、裾をフェードさせます（`data-length` = `medium` / `long`）。

ここで2つ間違えていました。

**ひとつめ。段はフォントサイズを変えるだけで、スタンプには届いていませんでした。**
`.od-emoji` がピクセル固定だったので、スタンプだけの札は段を踏んでも何も縮まず、3列目が
札の縁でただ切り落とされていました。いまは `1.6em` です ── 小サイズの12pxでちょうど従来の
19pxになり、そこから札のサイズにも段にも付いていきます。帯・一覧・編成ページは自分の高さが
あるので、それぞれ自分のpxを持ったままです。

**ふたつめ。入りきるかどうかは面積の話なのに、幅しか数えていませんでした。** スタンプは
幅が2文字ぶんですが、高さも1.5行ぶんあります。小サイズの札は文字なら8字入るところ、
スタンプは4個しか入りません。2と数えていたせいで段が遠すぎ ── 縮むのが10個目、フェードは
一度も来ませんでした ── 5個目で3列目が切れている横で、予算はまだ余っていると言っていました。
いまは3と数えます:

| 小サイズの札 | 入る数 | 段 |
| --- | --- | --- |
| 19.2px（そのまま） | 4個 | — |
| 14.4px | 6個 | `medium` |
| 11.2px ＋ フェード | 12個 | `long` |

文字のほうの段は動いていません。スタンプの数え方だけを直したので、`おはよう` が縮む条件は
以前と同じです。

### 同じものを何度も言っている札

そしてほとんどの札がそうです。チャットから掘った2609枚のうち**1150枚**が、絵の繰り返し
だけでできています ── スタンプ3つ、スタンプ5つ、`🦢✨` ×2。そのまま描くと小サイズの札は
5個を入れるために縮まねばならず、しかもその札はスタンプこそが中身です。

なので札のほうは**一度描いて数えます**（`🪽🫧🎶×2`）。小サイズで原寸のまま出せる札が
**48% から 85%** になります。

| 小サイズの札 | 原寸 | 一段 | 二段＋フェード |
| --- | --- | --- | --- |
| そのまま描く | 1250枚 | 1321枚 | 38枚 |
| ×N で描く | 2228枚 | 371枚 | 10枚 |

**繰り返されているものが、誰かが言ったものでなければなりません。** 絵は必ずそうです ──
同じスタンプがもう一度あるだけですから。文字はたいていそうではありません: `www` は単語
そのもの、`88888` は拍手、`てぇてぇ`・`よしよし`・`そうそう`・`ぎゅっぎゅっ` はどれも
「重ねること自体が語」です。`×N` と書くと語が割れます。

**分け目は終止符です。** `はい！はい！はい！はい！` はひとつの発話を4回言ったもので、
`はい！×4` とぴったり読めます ── `アンコール！×2`、`安心！×3`、`ちーよみ！×2` も同じ。
掘った中の「文字の繰り返し」354枚で、この線はきれいに通ります:

| | 枚数 | 例 |
| --- | --- | --- |
| 終止符がある → 数える | 14枚 | `はい！` `アンコール！` `安心！` `ちーよみ！` `サーターン！` |
| 無い → そのまま | 340枚 | `おお`151 `www`83 `ｗｗｗ`67 `GG`9 `うんうん`6 `ほうほう`5 … |

単位は2原子以上でなければなりません。`！！！！` の `！` は「言ったもの」ではなく
`www` と同じ側だからです。

**単位は最短のものを取ります。** スタンプ6個は「3個を2回」ではなく ×6 です ── どちらも
札を言い当ててはいますが、札なのは片方だけです。

そして**帯は省略しません**。札は読めるように縮め、帯は送られるものをそのまま出す ──
カーソルを置けば、`×5` が実際には何になるのかがその場で分かります。

## Nothing floats over the chat

パネルはチャットのいちばん下に置かれるので、その上に浮くものは何であれチャット本文を隠します。
そこで、浮かせる代わりに**パネル上部の帯を使い回します**。帯は状況に応じて顔を変えます。

| 状況 | 帯の中身 |
| --- | --- |
| 通常 | チャンネル名 ＋ 共通 ＋ 枚数 |
| 入力欄に何かある | 保存先の2ボタン |
| 札を編集中 | 「編集中」＋ ［更新］［やめる］ |
| プールを開いている | ［手持ち N］［プリセット N］の切り替え |
| 札やボタンにカーソル | 札なら中身そのもの、ボタンならその説明（`setPeek`） |
| 保存・削除・移動の直後 | 通知と「元に戻す」（`showToast`） |

右端はいつも操作です ── 「編成」、プールに札があれば「プール12」、プールを開いていれば
「閉じる」。**プールへの入口はもともと手札の下の横幅いっぱいのボタンでした**が、短いことを
ひとつ言うために1行を使っていました。帯はもともと「ほかに置けば場所を取るもの」の置き場
なので、そちらへ移しています。帯の操作は縮みません（`flex-shrink: 0`）── 譲るのは
チャンネル名のほうで、そちらには省略記号があります。

そのため、配信ページ側のUIに浮遊トーストはありません。読み上げ用の名前は `aria-label` で
別に付けています。

`title` が残っているのは**4か所だけ**です ── 引いた札の ＋ と保存先の2ボタン、そして
その2つが押せないときの理由。どれもブラウザ標準のツールチップで、帯が同じことを言えない
場面（押せないボタンにはカーソルの説明が出ません）に限っています。

**断られたことは、押した札の上に出します。** 帯は隅にあり、見る理由がありません ── そして
押して何も起きなかったときは、帯だけが「なぜ」を持っていました。押した札はカーソルの下に
あるので、そこで赤く震えます（動きを減らす設定なら色だけ）。帯の文はそのまま、ただし
唯一の知らせではなくなりました。

**起きたことは、起きたところが語ります。** 「札を更新しました」は札の中身がその場で変わり、
「編集をやめました」は入力欄が空になり、「◯◯を入れました」は10枚の札が現れます ── どれも
隅で言い直す必要がありません。消さなかったのは次の3つだけです:

- **「元に戻す」が付いているもの**（デッキから外した・削除した）── 取り消す入口がそこにしか無い
- **「同じ札がもうあります」**── 手札に新しい札は増えず、既にあった札が光るだけなので、
  見逃すと保存に失敗したように見えます
- **保存先の報告**（共通／このチャンネル専用）── 違いは札の上端の細い色帯だけで、
  それが何を意味するかを先に知っている必要があります

**知らせは、次に何かした瞬間に消えます。** 帯は1行しかないので、通知は保存先のボタンと同じ
場所を取り合います ── 打った内容についてのエラーが、それを直して押し直すためのボタンを
6秒間隠していました。起きたことの報告は、次のことが起きた時点でもう報告ではありません。

同じ理由で、札を編集し始めたときの「直したら『更新』を押してください」は**やめました**。
帯はそのあとすぐ「編集中 ［更新］［やめる］」になります ── 同じ文を、押せるボタンで言って
いるのに、文のほうがボタンを隠していました。

**札にカーソルを置くと、帯はその札を出します ── 文字ではなく、絵で。** 札は小さく、入りきら
なければ縮んで消えていくので、帯のほうが場所があります。

これは一度やめて、戻した機能です。やめた理由は正しかったのですが、もう当てはまりません ──
当時の帯は札を**文字にしか**できず、メンバー絵文字の文字はYouTubeがそれを整理している名前
なので、`:_tadaima:` ×3 が `tadaimatadaimatadaima` と読み上がっていました。いまは帯も絵を
描くので（[Standard emoji](#standard-emoji) と同じ `toFragment(…, { preview: true })`）、
出るのは札に出ているものそのものです。

**ただし、札が自分について語っていることは言いません。** いま言われている札は隅で呼吸して
いるので、5人か50人かですることは変わりません ── 変えるのは点のほうです。引いた札に
「＋で保存」と教えるのも同じで、その ＋ は札の上の、ほかの札と同じ場所にあります。
鍵のかかった札だけは例外で、そこは帯にしか言えることがないので**言葉**になります。

**YouTube自身のツールチップを呼び出さないこと。** `shared-tooltip-text` はYouTubeの属性で、
読むのは `tp-yt-paper-tooltip` です ── `collectTokens` がその要素を除外しているのは、
まさにそれがこの木の中に現れるからでした。パネルはライブチャットのレンダラの中に間借りして
いるので、札の面にこの属性が付いていると、カーソルを置いた瞬間にYouTubeが `:_ただいま:` を
チャットの上に浮かせます。この属性が要るのは**入力欄に入れる側だけ**で ── そこから読み戻した
ときに、メンバーが要るかどうかを言える唯一の手がかりだからです ── 札の面は読み戻されないので
付けません。

逆に、**YouTube 自身がその場所を使いに来ることもあります**。スーパーチャットを開くと、YouTube は
入力欄を消さずに畳んで、同じ隅に自分のパネルを出します。畳まれた要素も `querySelector` には
答えるので、「見つかった」を「使える」と読んでいたパネルは、そのまま SC パネルの上に描き続けて
いました。いまは**描かれているか**（`getClientRects()`）で判断し、畳まれていれば身を引きます。

合図は入力欄レンダラの属性変化だけを見ます（今日の YouTube では `product-picker-open`）。
属性名は書いていません ── 名前が変わっても「もう一度見ろ」は届き、判断そのものは測って行うので
壊れません。チャットのメッセージごとに走る経路では測りません。レイアウトを強制するからです。

## Taking someone else's comment

チャット欄のコメントにカーソルを置くと、右端に ＋ が出ます。押すと**その場で**保存先の2つが
現れます ── チャンネルの色の丸と、灰色の丸。押したほうに保存され、プールとデッキの両方に入ります。
メン限スタンプ入りなら灰色は押せません。

**選択肢は押した場所に出ます。** 最初はパネル上端の帯に出していましたが、帯はチャットの ＋ から
遠く、設定ページの下端に警告を書いていたのと同じ間違いでした。

言うほうがしたいときは **⇧＋クリック**で入力欄に入ります（札を ⇧＋クリックすると送信になるのと
同じ ⇧ です）。判断も重複の扱いも既存の保存経路がそのまま担当するので、この機能が持っているのは
「どこから中身を取るか」だけです。

読み取りは `tokens.collectTokens(message)` ── チャット連動の並び替えが以前から使っているものと
同じ呼び出しです。コメントと下書きは形が同じ（文字の中に `<img data-emoji-id>`）なので、
新しい解析は要りません。

ボタンはYouTube自身が各行の右に空けている32pxのガター（絶対配置・ホバーまで不可視）のすぐ内側に
入ります。**カーソルのある1行にしか存在しません** ── DOMに置くボタンは常に1つで、行から行へ
移るだけです。絶対配置なので本文は詰まらず、1行ごとにボタンを撒く必要もありません。

## Drawing a card from the chat

チャットが**バーストしたとき**だけ、持っていない反応を1枚、手札の左端に差し込みます。
麻雀でツモるのと同じで、打ってもいいし、手札に入れてもいい。

```
● 稀羽すう    14枚                      [編成]

  ┊888┊    ╭──╮╭──╮╭──╮╭──╮╭──╮╭──╮╭──╮
  ┊   ┊    │札││札││札││札││札││札││札│
   ↑ 引いた札（破線・扇の外・呼吸する縁・すこし離して）
```

**重なりは左が上です。** 兄弟要素は後のものが上に描かれるので、放っておくと右端の札がいちばん上、
左端 ── **いちばん使う札**が、いちばん下に埋もれます。手札は大事な順に並んでいるのだから、
重なりもそう並べます。引いた札の光が隣に切られていたのも、同じ順番のせいでした。

**左端は「手札の左端」ではなく、独立した場所です。** 手札が空のときは左端にする手札が無いので、
引いた札が真ん中に出てしまっていました。いまは引いた札が自分の区画を左端に持ち、手札は残りの幅で
中央に扇を作ります。

**行を増やしません。** パネルはチャットのいちばん下にあるので、行が増えればその分チャットが狭く
なります。代わりに手札が重なりを詰めて場所を空けます ── 400pxのサイドバーで小サイズなら、
7枚の重なりが8pxから17pxになって1枚ぶんが生まれる、という程度です。詰めきれない幅のときは
引きません。

**いつ出るか、どれだけ残るか、どれだけ速く忘れるかは、設定で変えられます。** 部屋の賑やかさは
チャンネルごとに違いすぎて、こちらで決め切れる数字ではないからです。

| 設定 | 左 | まんなか | 右 |
| --- | --- | --- | --- |
| 引きやすさ | ひかえめ 8回・4割 | **ふつう 6回・3割** | よく引く 4回・2割 |
| 残る時間 | **ながめ** 60秒 | **ふつう 30秒** | みじかめ 15秒 |
| 反応の速さ（半減期） | ゆっくり 30秒 | **ふつう 20秒** | はやい 10秒 |

落ち着いているほうが左です。残る時間だけ長いほうが左に来るので、3行とも同じ向きに
読めます。

残る時間と反応の速さは、段のかわりに**秒数を直接書くこともできます**（下記「段と、秒」）。

設定ページでは、この3つは**それが効くところに置いてあります** ── 引きやすさと残る時間は
「チャットから引く」の節、反応の速さは並び順のすぐ下。どれも一度は「手札の並べ方」に
まとめて置いていましたが、そこは札の大きさと行数の場所で、**同じ節にあるというだけで
関係があるように読めてしまいます**。

**数字ではなく段で出しているのは、独立していないからです。** 何回言われたかと、部屋のどれだけを
占めたかは、二つで一つの「波」を決めています。別々に触れるようにすると「2回で5割」のような、
意味をなさない組み合わせが作れてしまいます。設定ページの説明には、その段が実際にいくつなのかを
そのまま書いてあります ── `ふつう` という名前は、それが何をするのか誰にも教えないので。

値は `src/store.js` の `TUNING` に全部あります。段の意味を変えるのは一行です。

**いつ出るか（既定）。** 12秒のあいだに**6回以上**、かつ**その間に流れた発言の3割以上**（割合の分母は
発言の時刻だけを別に数えています ── 文面を覚えておく数には上限があり、その上限が分母を兼ねていた
ころは、速いチャットで「部屋の3割」が実際より大きく見えていました）。二つ要るのは、
どちらか片方では意味をなさないからです ── 回数だけではチャットの勢いが分からず、「4回」は静かな
部屋では波でも賑やかな部屋ではただの雑談で、実際それで誰も乗っていない言葉が出ていました。
割合だけなら、ほとんど無言の部屋で最初の2発言が100%になってしまいます。本物の波では、みんなが
他のことを言うのをやめます ── それを見ています。

並べ替えのほうは新しさで重み付けした緩い一致ですが、こちらは**完全一致**です ── `きちゃ` と
`きちゃきちゃ` は、並べるときは同じ反応でも、**打つときは違う言葉**なので。

**出たあとは30秒とどまります**（期限が来たら自分で描き直しに行きます ── 期限に気づくのは描き直しの
ときだけなので、チャットが静まると誰も気づかないまま居座っていました）。 毎回引き直すと反応から反応へちらつき、カーソルの下で入れ替わる
札は無いよりたちが悪いからです。デッキに入れた時点でその札の役目は終わります。

**とどまるあいだ、描き直しもしません。** チャット連動は数秒ごとに描き直しますが、描き直せば要素は
新しくなり、新しい要素はアニメーションをやり直す ── 引いた札が数秒おきに左から滑り込み直して、
跳ねているように見えていました。いまは「パネルが映しているもの」に変化が無ければ描き直しません。
チャットの回数が増えただけ、は変化に数えません（札が光り始めた／やんだ、は数えます）。それでも
何かの都合で描き直しになったときのために、滑り込みは本当に新しい札のときだけで、光は前の続きから
始まります。

**打つか、取っておくか。** 札を押すと入力欄に入り、そのまま送れば打ったことになります。取って
おくときは札の **＋** を押すと、その場に保存先の2つが出ます ── 送信を経由しないので、「札を
クリックしたら自動で送信する」を入れていても使えます。⇧＋クリックなら保存せず入力欄にだけ
入ります。

出さないもの:

- すでに手札にある反応（放っておいてもチャット連動で前に出ます）
- 送れないメン限スタンプ ── 別チャンネルのもの、そしてこのチャンネルのものでもメンバーでない
  あいだ。押して失敗する札は、無いほうがましです。**メンバーであれば出します**（[Member
  emoji](#member-emoji)）── 引いたあとメンバーでなくなれば、その場で引っ込めます

設定の「チャットから引く」で止められます。

### 段と、秒

「引いた札が残る時間」と「反応の速さ」は段で選びますが、**秒数を直接書くこともできます**。
段のほうが既定として正直です ── あれは測った値ではなく手触りの判断なので ── が、自分の
配信のチャットを長く見てきた人は、こちらが用意できるどの数字よりいい数字を持っています。

| | 左 | まんなか | 右 |
| --- | --- | --- | --- |
| 引いた札が残る時間 | 60秒 | **30秒** | 15秒 |
| 反応の速さ | 30秒 | **20秒** | 10秒 |

長いほうを左に置いています ── 左ほど落ち着いていて、右ほど目まぐるしい。

**「引きやすさ」には秒の欄がありません。** あれは2つの数（何件と、部屋の何割）が互いに
噛み合って初めて意味を持つもので、ばらばらに決められるようにすると「2件で半分」のような
意味のない組み合わせを招きます。

秒は**書き込む時点で確定させます**（`cleanSettings`）。空欄は `NaN` として届きますし、
用意していない段の名前が入ってくると、読むたびに黙ってまんなかの段になってしまいます ──
1秒から10分の間に収め、読めない値はその場で断ります。

## Chat-driven sort

「チャット連動」は、いま多い反応に合う札を前に出します。数えるだけでなく、**新しさで重みを付けます** ──
1件は `2^(-経過/半減期)` ぶんで、半減期は既定で20秒（「反応の速さ」で変えられます）。
**捨てるのは半減期の4.5倍より古いもの**（既定で90秒、ただし最低でもバースト窓の12秒）で、
その時点で重みは4%ほどなので、窓から落ちること自体は見えません。半減期を10分にしても
固定の90秒で切られる、ということにならないように、窓のほうが付いていきます。

比較は正規化した署名どうしで行うので、書き方の揺れは吸収されます。

| チャット | 手札の札 | 一致 |
| --- | --- | --- |
| `88888888888` | `888` | ○ |
| `はい！はい！はい！はい！` | `はいはい` | ○ |
| メン限スタンプ ×4 | 同じスタンプ ×1 | ○ |
| `わこつ〜` | `わこつ！！！` | ○ |
| `おつ` | `888` | × |

**なぜ重みを付けるのか。** 平らに数えていたころは、大量の拍手のあと次の曲が始まっても拍手が先頭に
居座りました ── 窓の中の1件はどれも同じ重さで、端から落ちる瞬間まで満額だったからです。いまは
80秒前の拍手40件は2.5点なので、新しい反応が3件で追い越します。しかも落ち方が滑らかなので、
窓から抜けた瞬間に順番が跳ねることもありません。

- 並べ替えは4秒に1回まで。カーソルが札の上にある間は動きません（配信中に札が指の下で入れ替わるのを防ぐため）
- 帯に出る「いまチャットで◯回」は素の件数です。順番を決めるのは重み、見せるのは件数
- チャットが静かなときは「最近よく使う順」に自動でフォールバックします
- 実装は `src/trending.js`。署名は「連続の繰り返し」と「全体の繰り返し」を1回分まで畳んで作ります

## 言語

日本語と繁体字中国語。**設定ページで選べます** ── `chrome.i18n` はブラウザの言語に従うだけで
中から切り替えられず、それはここでは逆に困ります（日本語の配信を、中国語のChromeで見ている人が
どちらを選ぶかは、その人しか知りません）。選んでいなければブラウザに合わせます。

言葉は `src/i18n.js` の表に全部あります。**日本語が原文**で、訳の無いものは日本語のまま出ます ──
鍵の名前（`bar.global`）よりは、読めない言語の文であるほうがまだ文だからです。逆に**存在しない鍵**は
鍵の名前がそのまま出ます。そちらはバグで、出ていれば気づけます。

- 画面側は `data-i18n="鍵"`（属性なら `data-i18n-placeholder` など）。中に残してある日本語は
  スクリプトが動く前に出る控えで、空のページよりはましという役割です
- `$1` `$2` は呼ぶ側が順に埋めます。名前ではなく番号なのは、語順が言語で変わっても
  番号のほうは動かないからです
- `tools/check-i18n.mjs` が、**コードに直に書かれた日本語**・存在しない鍵・誰も使っていない鍵・
  原文と `$1` の数が合わない訳を全部出します。翻訳は「95%終わった」状態が長いので、
  残りを人が数えないで済むようにしてあります

## 推し色

デッキごとの色。保存されるのは**色相の数値ひとつ**だけで、明度と彩度はパレットが固定します
（`oklch(0.74 0.19 H)`）── そうしておかないと、暗いパネルの上で読めない色を選べてしまうからです。
だから色は「何色か」ではなく「**どの色相か**」だけを訊かれます。

選び方は3つ、どれも同じ色相になります:

- **8色の丸** ── よく使う色
- **色相スライダー** ── 8色以外。軌道はパレットそのものの色相環なので、見えているものがそのまま
  デッキの色になります
- **色の丸（`input[type=color]`）** ── OSのカラーパネルが開きます。カラーコードの入力も、
  スポイトも、ここにあります。拾った色は色相だけ取り出されます

**最初の色。** `src/store.js` の `OSHI_HUES` に書いたチャンネルは、その色でデッキが生まれます。
書いていないチャンネルはIDのハッシュから8色のどれかになります ── 適当ですが、同じIDなら毎回同じです。
どちらにしても、あとから変えた色がいつでも勝ちます。

```js
const OSHI_HUES = {
  "UCPb47fygHcFbRp_y05mS0IA": 250,
};
```

同梱の表は**空**です。書き方の例であって、中身はこれから。

sRGBの外に出る色相は、チャンネルを切り詰めるのではなく**彩度を落として**戻します。切り詰めると
色相が最大9度ずれてしまい、ずれるのはまさに選んでいる当のものだからです。

## Member emoji

メン限スタンプは、それを配っているチャンネルでしか送れません。OshiDeckは `data-emoji-id` の
チャンネルID接頭辞から持ち主を判定し、別の配信では札を薄く表示してクリックを止めます。

**ただし接頭辞があること自体は「メンバー限定」ではありません。** YouTubeは誰でも使える絵文字を
配っていて（`:shelterin:`・`:face-red-heart-shape:` など）、それにもチャンネル接頭辞が付いています ──
配信者ではなく、ただの視聴者アカウントのものです。接頭辞だけを見ていたころは、**誰でも送れる札を
どこでも永久にロックしていました**。

見分けるのは**ショートカット**です。メン限は `:_名前:`、無料のものはアンダースコアがありません。
読む場所が2か所あって、しかも食い違うのが罠でした:

| | 配信ページのDOM | チャットの書き出し（yt-dlp） |
| --- | --- | --- |
| 表示名 | `alt="ぺここ"` | `accessibility.label` |
| ショートカット | `shared-tooltip-text=":_ぺここ:"` | `shortcuts: [":_ぺここ:"]` |

`alt` は表示名なので、そちらを見ているとアンダースコアはどこにも無く、**すべてのメン限スタンプが
解除されて**しまいます。ホバーしなくても `shared-tooltip-text` は読めます（実測）。

ショートカットを集めるようになる前に保存した札には、答えようがありません。その場合は
**メンバーが要る側に倒します** ── 逆に倒すと「押せるのに送れない札」になり、それはロックが
防ごうとしているものそのものだからです。

**メンバーかどうかも見ます。** 配っているチャンネルにいても、メンバーでなければ送れないので、
そこも同じように止めます ── ただし理由が違うので、言うことも違います。「別チャンネルのスタンプ」は
どうにもなりませんが、「メンバー限定」はメンバーになれば使えます。

判定に使うのは、**入力欄の横にある自分のバッジ**です:

```
yt-live-chat-message-input-renderer          ← パネルが間借りしているのと同じ要素
  #input-container > yt-live-chat-author-chip   ← 「自分」の身分
    span#chat-badges
      yt-live-chat-author-badge-renderer[type="member"]
```

実測して分かった、間違えやすいところが3つあります:

- **範囲を絞らないと必ず誤判定します。** メンバーがいないチャンネルなど無いので、文書全体を
  探せばバッジは必ず見つかります ── 入っていない配信で数えたら**57個**ありました。全部他人のです
- **`hidden` は答えではありません。** 別窓のチャットでは、メンバーであってもチップに `hidden` が
  付いています。バッジがあるかどうかだけが答えです
- **HTMLの中に会員フラグはありません。** `isSponsor`・`loyaltyBadges`・`sponsorOnly` ──
  どれも存在しません。DOMを見る以外に道がありません

答えは3つあります。**はい・いいえ・まだ分からない**。チップそのものが無いときは「まだ」で、
そのときは何も止めません ── 間違った鍵は、送れない札より始末が悪いからです。チャットを読み込み
直して測ったところ、**入力欄とバッジは同じ描画で現れます**（ずれ0ms）。パネルが立ち上がれる時点で、
答えはもう出ています。

**押すときにもう一度訊きます。** カーソルが札の上にある間、手札はわざと固まります ── 指の下で
入れ替わらないように ── ので、その間にメンバーが切れても鍵は古いままです。引いた札にいたっては
そもそも鍵がありません（誰のデッキにも入っていないので）。だから最後に効くのは押した瞬間の答えです。
古い鍵が効くのは**ページが答えられないときだけ**で、答えられるならそちらが勝ちます ── そうでないと、
固まっているあいだにメンバーに戻った札が、いつまでも断られ続けます。

**送るのは札ではなく入力欄です。** 札への ⇧＋クリックはその場で送ります。送らずに置くだけなのは
**引いた札の ＋** への ⇧＋クリックのほうで、送れないスタンプが
そこに残ったまま次の札を押すと、まとめて出ていってしまいます。だから送る直前に見るのは、
押した札ではなく**入力欄の中身**です。

**鍵のかかった札は、並び順が何であっても最後に回します。** デッキからは外しません ── メンバーに
戻れば元の位置に帰ってきます ── が、押せない札が手札の途中にあると、次に送るものを探している目が
ちょうどそこで止まります。

**まだできないこと。** バッジが言うのは**年数**（「メンバー（2年）」）であって、**等級**ではありません。
上の等級にしか配られないスタンプがあるチャンネルでは、「メンバーかどうか」までしか答えられません。

保存済みのCDN URLは古くなることがあるので、チャットに流れてきたスタンプの `src` を随時
拾い直し、描画時はそちらを優先します（`src/tokens.js` の `harvestEmoji` / `freshSrc`）。

## Standard emoji

`👏` や `🦢✨` のような普通の絵文字を、YouTubeはシステムフォントで描いていません。Live Chatは
**全部Googleの画像に差し替えます**。だから同じ一言が、チャットでは1つの絵、その隣の札では別の絵に
なります ── Windowsなら Segoe UI Emoji で3つめの絵です。札とは「これから送る一言の絵」なので、
**チャットと同じ画像を使います**。

**札の上だけです。** トークンとしては `text` のままで、入力欄に入るのも文字のままです。そこで絵に
するのはYouTube自身のレンダラーであって、代わりに `<img>` を置いても解決すべき emoji id がありません。
境目は `toFragment` の引数そのものです:

```js
toFragment(tokens, { preview: true })   // 札 ── 画像
toFragment(tokens)                      // 入力欄 ── 文字
```

**画像のURLは保存しません。文字から出ます。** 1配信分のチャット書き出しで数えた標準絵文字115種は、
115種ともYouTubeが実際に返していたURLと一致しました:

```
https://fonts.gstatic.com/s/e/notoemoji/15.1/<コードポイント>/72.png
```

落とし穴が4つあって、全部URLを叩いて確かめました:

- **コードポイントではなく書記素で切ります。** `👏🏻` は手＋肌の色、`😵‍💫` は顔2つ＋結合子、
  `👨‍👩‍👧` は人3人＋結合子2つ。どれも**1枚の絵**です。`Intl.Segmenter` が全部正しく切ります
- **`Extended_Pictographic` だけでは足りません。** 旗（`🇯🇵`）の中身は文字2つ、キーキャップ
  （`1️⃣`）の中身は数字なので、どちらも「絵文字ではない」と答えます
- **4桁に0埋めします。** `1️⃣` の `1` はコードポイント `31` ですが、ファイルは `0031_20e3` です。
  `31_fe0f_20e3` は404
- **異体字セレクタ（`FE0F`）は落とします。** YouTube自身が自分の emoji id から落としていますし、
  ファイルは付けても付けなくても返ります。ただし `2764_fe0f` は存在して `1f44f_fe0f` は404なので、
  残したままだと**半分は動いてしまい**、バグが運に見えます

絵が無い書記素（`™`・`♻` など）は404で返ってくるので、`error` で文字に戻します ── それが
この変更の前に札が見せていたものです。

**札の幅も同じ数え方にします。** 絵文字を文字として数えると `🦢✨🦢✨🦢✨` は9幅になり
（`✨` は1 UTF-16単位、`🦢` は2）、同じ6枚の絵が別の長さとして薄くなります。`splitEmoji` は
札の描画と幅の計測の両方が使う、ひとつの答えです。

## Icons

2枚の絵で4サイズを作ります（`tools/make-icons.sh`）。

| サイズ | 絵 | どこに出るか |
| --- | --- | --- |
| 16・32 | 札1枚 | ツールバー |
| 48・128 | 扇（札3枚） | 拡張機能の一覧、インストール時、ストア |

扇はパネルそのものの形で、これが何なのかを一番よく言い表します ── ただし**16pxでは潰れます**。
ツールバーは「見つける」ための場所なので、そこは札1枚に落とします。地の色も縁の丸みも
推し色の帯も同じなので、並べても同じものに見えます。Chromeがサイズごとに別ファイルを
受け取れるのは、まさにこのためです。

## Layout

`src/layout.js` — 扇の幾何。1行の枚数は幅から決まります。

| パネル幅 | 1行 | 2行合計 |
| --- | --- | --- |
| 280px | 4枚 | 8枚 |
| 320px | 5枚 | 10枚 |
| 360px | 6枚 | 12枚 |
| 400px（サイドバー） | 7枚 | 14枚 |
| 560px | 10枚 | 20枚 |
| 760px（別ウィンドウ） | 14枚 | 28枚 |

行は「1行目を上限まで詰める」のではなく2行に均等割りするので、札が8枚しかないときに `7 + 1` とぶら下がらず `4 + 4` に揃います。
